# AuroraClassic 全專案 Code Review 與 12.1 Migration

日期：2026-08-11

## 範圍與證據基準

- AuroraClassic：逐檔讀完 126 個 Lua，包括 5 個頂層檔、58 個 `FrameXML` 模組與 63 個 `AddOns` 模組。
- 載入清單：`FrameXML.xml` 的 58 個 `<Script>` 與 58 個 Lua 完全相符；`AddOns.xml` 的 63 個 `<Script>` 與 63 個 Lua 完全相符。
- 另讀：`AuroraClassic.toc`、兩份 XML、`.pkgmeta`、release workflow、README、AGENTS 與既有 code-review 記憶。

## 結論摘要

- 目前工作樹仍是 `Interface: 120005`，尚未完成 12.1 遷移。
- 已確認 6 個 12.1 結構性硬斷點：ChatFrame、Fonts、AchievementUI、Delves Companion、Housing Dashboard、Weekly Rewards。
- 另確認 Weekly Rewards 選獎、Alert pooled hook、ChatBubbles option、GMChat hook 等既有缺陷。
- 12.1 的 script binding、event registration、parent/layout 與 texture-parent 限制顯著加強；Aurora 的共用 helper 與動態 HookScript 必須做正式服驗證，不能以廣泛 nil guard 或 `pcall` 代替。
- CooldownViewer、Communities 與 Voice notification 有明確 secret data-flow 風險；資料流已由 API 文件確認，但實際觸發條件仍需 12.1 正式服驗證。

## 載入與架構問題

### ADDON_LOADED 清除錯 key

- Aurora：`AuroraClassic/Init.lua:67-70`。
- 由事件參數 `addon` 取得並執行 theme，卻清除外層 `addonName`（固定是 `AuroraClassic`）。
- 結果是 Aurora 之後才載入的 Blizzard theme 仍殘留在 `C.themes`。正常 ADDON_LOADED 通常只送一次，因此主要後果是錯誤的 lifecycle 契約與 retained closure，不應誇大成每次都會重複 skin。

### 共用 helper 藏在特定 addon 模組

- `B.ReplaceIconString` 定義於 `Blizzard_AnimaDiversionUI.lua`，caller 橫跨 FrameXML 與多個 AddOns。
- `B.SetCurrenciesHook` 定義於 `Blizzard_RuneforgeUI.lua`，跨檔 caller 是 `Blizzard_AzeriteUI.lua`。
- 現行 `AddOns.xml` 先於 `FrameXML.xml` 且檔案順序剛好成立，但這是脆弱的隱式載入契約。若 helper 確屬共用，應移入 Core；否則 caller local 化。

### 其他已確認載入契約

- FrameXML 的 `B.ReskinIconSelector`、`B.ReskinModelControl`、`B.ReskinTooltip` 也有跨檔依賴；現行 XML 與 theme 執行順序成立，改順序時必須同步查 caller。
- AddOns 共 79 個 `C.themes` key，另有 FrameXML 的 `Blizzard_TimeManager`，合計 80 個。除了上列 4 個 MAINLINE 不存在 key，其餘 key 均已對照實際 addon；ExpansionLandingPage／MajorFactions 是 key 有效、target 失效。
- 12.1 大量 addon 新增 `[Bootstrap]` 檔。必須實測 bootstrap-only 階段的 `C_AddOns.IsAddOnLoaded(name)` 兩個回傳值與最終 ADDON_LOADED 時機，確認 Aurora 不會在主 XML/Lua 尚未完成時執行 theme。

## Secret／secure／12.1 API hardening

### 高風險資料流

1. `AddOns/Blizzard_CooldownViewer.lua:74-87`
   - post-hook 讀 `data.auraInstanceID`，呼叫 `C_UnitAuras.GetAuraDispelTypeColor`，再分支與讀 RGB。
   - 12.1 文件標示 `RequiresUnitAuraAccess`、`RequiresValidUnitAuraInstance`、`SecretWhenUnitAuraRestricted`；CooldownViewer 會掃 player 與 target，且 12.1 新增 secure chunk。
   - Blizzard trusted code 使用同 API 不代表 Aurora tainted hook 安全。需重新設計 restricted-aura 路徑，不可只以 `if color` 或 early return 留下 pooled frame 舊邊框。

2. `AddOns/Blizzard_Communities.lua:62-73,336`
   - post-hook 取得 pooled row 的 `memberInfo`，boolean-test `classID`，再查 class table。
   - `C_Club.GetMemberInfo` 在 chat messaging lockdown 會成為 secret；`classID` 不是 NeverSecret。
   - 外觀非必要時應在 lockdown 避免解析 member payload，或只使用公開 widget state。

3. `FrameXML/ChatFrame.lua:110-117`
   - Voice notification GUID 來源 `C_VoiceChat.GetMemberGUID` 在 chat messaging lockdown 可為 secret。
   - 後續 `GetPlayerInfoByGUID` 的衍生 class 被 boolean-test 並作 table key，屬需移除的 secret 消費路徑。

### 12.1 widget API 限制新增

- `HookScript`／`SetScript`：新增 `RequiresAssignableScript`、`SecretArguments=NotAllowed` 與 `ForbiddenAspect.ScriptBindings` 檢查；HookScript 現在回傳 success bool。
- event registration／unregistration：新增 `ForbiddenAspect.EventRegistrations` 檢查與傳播。
- `SetParent`、button texture setters、`SetStatusBarTexture`：新增 parent-change 檢查。
- `SetPoint`／`SetAllPoints`：新增 forbidden layout aspect inheritance 檢查。
- Aurora 的高風險表面包括 pooled alert/Loot/LFG/ObjectiveTracker hooks、`B.HideObject()` 對 frame 的 `UnregisterAllEvents`＋`SetParent`、共用 button/statusbar helpers，以及大量 reanchor。
- 目前沒有證據證明所有 caller 都會失敗；應以精確 frame、combat、forbidden aspect 與正式服情境驗證，不可廣泛包 `pcall`。

### 共用 helper 的 secret 風險

- `Core.lua:269-273` 的 icon border color hook會比較 `r/g/b`；若來源 SetVertexColor 參數為 secret，這條 helper 不安全。需找具體 restricted caller，不把它當成通用安全 sink。
- `Core.lua:1195-1202` 全域覆寫 `BackdropTemplateMixin:SetupTextureCoordinates`，secret width 時跳過原生更新。這能避免直接算術，但可能留下舊 backdrop 幾何；height/effectiveScale 也未逐項確認。需正式服驗證，不宣稱已安全。
- `B.ReplaceIconString` 會對文字做 nil/空字串比較、`gsub` 與 count 比較；只能用於已確認非 secret 的文字來源。

## Pool／ScrollBox 與第三方整合待驗證

- Artifact appearances 預先 Acquire 6 個 set 與 24 個 slot 是固定數量 workaround；Blizzard Refresh 會先 ReleaseAll，因此不直接判為 pool leak，但 already-open 載入路徑與未來數量超過固定值仍脆弱。
- 需要重點實測的動態模組：Collections、AuctionHouse、EncounterJournal、Garrison、LFGList、LootFrame、ObjectiveTracker、PerksProgram、PlayerChoice、PlayerSpells、Professions、CustomerOrders、Soulbinds、Stable、Trainer、Transmog、WeeklyRewards。
- WarPlan／VenturePlan 只在 Garrison theme 執行當下探測；需以實際第三方 TOC 驗證依賴與載入順序。
- RaidUI 的 template 仍是 `SecureUnitButtonTemplate`；Aurora 沒改 secure attribute，但會依固定 region index 建 backdrop，必須測戰鬥中首次載入、拖成員、右鍵選單與 taint。

## 遊戲內測試矩陣

- 基本：冷登入、`/reload`、關閉重開。
- LoD：Aurora 先載入再首次開 Blizzard UI；Blizzard addon 已載入後才載入／重載 Aurora。
- 12.1 blocker：ChatFrame、`/rw`／boss emote、Achievement search/comparison、Brann 配置四 slot、Housing 三個頁面／dropdown、Great Vault 兩 concession／選獎。
- Pool：捲出／捲入、ReleaseAll／reacquire、資料切換、搜尋／篩選、非同步 item load。
- Combat／secure：戰鬥中開啟、刷新、拖曳、右鍵選單；離戰後恢復。
- Secret：restricted aura、chat messaging lockdown、voice notification。
- GUI：ChatBubbles 關閉後 reload；Shadow=false 的 VenturePlan 路徑；FontScale 多次 reload 不累乘。
- 新 UI：SocialUI enabled/disabled、PVP Training Ground Arena、Housing Collection/Initiatives/Blueprint、Guild Discord tab、CooldownViewer 新 filter/alerts。

## 已撤回或確認不是問題

- `SetTextColor("P", 1, 1, 1)` 是 Blizzard 現行接受的呼叫形式，不是參數錯誤。
- EquipmentFlyout 的 width `+3` 不會無界累加；原生每次 UpdateItems 會先重設寬度。
- Artifact appearance 預先 Acquire 是固定數量脆弱 workaround，但現行 Refresh 先 ReleaseAll，不能直接稱為 pool leak。
- Transmog `SituationsFrame:Init` hook 時機成立；12.1 `TransmogWardrobeMixin:OnShow()` 每次都會呼叫 Init。
- ObjectiveTracker progress bar 的 `bar.Icon` 由原生 GetProgressBar 在 hook 前保證建立，現行不是 nil 問題。
- Calendar 清除 Today OnUpdate 只停止已被移除的 glow fade；未找到功能性行為損失。
- NavigationBar／TutorialFrame 的直接 SetScript 經現行 Blizzard script 核對，未確認功能回歸；仍須接受 12.1 ScriptBindings 實測。
- ColorPicker、Splash、UIWidgets 的搬移目前保留 Aurora 所用 globals／結構；RaidUI、TrainerUI 等 TOC 拆分也保留 addon key。
