## 載入與架構問題

- Aurora：`AuroraClassic/Init.lua:67-70`。

- 這些 assignment 在 Aurora 自身所有 Script 載入時已完成，theme closure 之後才執行，因此目前不是「XML 順序碰巧成立」的 runtime bug；真正問題是模組所有權與刪檔耦合。若 helper 確屬共用，應移入 Core；否則 caller local 化，且刪除來源模組前同步處理所有 caller。

CooldownViewer／Communities 的完整風險描述、修法、可見取捨與測試矩陣另見 `2026-08-12-secret-safe-cooldownviewer-communities.md`。

### 12.1 widget API 限制新增

- `HookScript`／`SetScript`：新增 `RequiresAssignableScript`、`SecretArguments=NotAllowed` 與 `ForbiddenAspect.ScriptBindings` 檢查；HookScript 現在回傳 success bool，但 assignable-script 前置條件的 failure mode 是 Error，不能只靠檢查回傳值處理。
- event registration／unregistration：新增 `ForbiddenAspect.EventRegistrations` 檢查與傳播。
- `SetParent`、button texture setters、`SetStatusBarTexture`：新增 parent-change 檢查。
- `SetPoint`／`SetAllPoints`：新增 forbidden layout aspect inheritance 檢查。
- Aurora 的高風險表面包括 pooled alert/Loot/LFG/ObjectiveTracker hooks、`B.HideObject()` 對 frame 的 `UnregisterAllEvents`＋`SetParent`、共用 button/statusbar helpers，以及大量 reanchor。
- 目前沒有證據證明所有 caller 都會失敗；應以精確 frame、combat、forbidden aspect 與正式服情境驗證，不可廣泛包 `pcall`。

### 共用 helper 的 secret 風險

- `Core.lua:269-273` 的 icon border color hook會比較 `r/g/b`；若來源 SetVertexColor 參數為 secret，這條 helper 不安全。需找具體 restricted caller，不把它當成通用安全 sink。
- `Core.lua:1195-1202` 全域覆寫 `BackdropTemplateMixin:SetupTextureCoordinates`，secret width 時跳過原生更新。這能避免直接算術，但可能留下舊 backdrop 幾何；height/effectiveScale 也未逐項確認。需正式服驗證，不宣稱已安全。
- `B.ReplaceIconString` 會對文字做 nil/空字串比較、`gsub` 與 count 比較；只能用於已確認非 secret 的文字來源。
